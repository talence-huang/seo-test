## 0. 摘要

| 研究問題 | 回答 | 主要證據 |
|---|---|---|
| **RQ1** 用程式寫成、每一步都可觀察的研究迴圈，能否在有限預算下從數萬頁網站找到正確結論？ | **能**。在 2 萬頁級的模擬網站上，平均約 37 次抓取就得出與標準答案一致的結論；每一步的決策、理由、分數明細與證據都可觀察。 | 測試集 18 / 18 正確（FakeLLM）；真實 Opus 在 s1、s3 正確（每個 episode 約 US$0.32）；抓取上限 20 次時仍 17 / 18 正確；所有評測 episode 安全違規 0 |

| **RQ3** 失效處置與自治邊界能否由程式保證，而不依賴 LLM 自律？ | **能**。即使 LLM 被完全攻陷、每個角色都照注入頁的指示輸出，Agent 也沒有越界抓取或改變結論；預算延長、範圍擴大等高風險動作都會硬暫停等待人工核准。 | 06 §3 測試矩陣全數通過（`tests/test_autonomy.py`、`tests/test_failures.py`）；LLM 40% 錯誤、網路 25% 錯誤、解析器 15% 崩潰、程序硬中斷皆完成且結論不變 |

## 1. 研究設定

| 項目 | 設定 |
|---|---|
| 環境 | SimWeb：確定性的模擬網際網路。每個情境有自家站與 2–3 個競品站（主要競品約 2 萬頁）、robots / sitemap、陷阱、WAF、429 / 5xx、損壞 HTML、注入頁、模擬排名與歷史快照 API |
| 標準答案 | 由情境中的事件自動推導（關鍵主張、干擾項、混淆因子），評分不採信 Agent 的自我報告 |
| 情境 | 6 個：訓練集 s1–s4、測試集 s5–s6（永不用於學習）；2 種目標 × 3 種網站類型 |
| 種子 | 同一情境可換世界種子：因果結構相同，網址、頁面與雜訊不同。評測每個測試情境用 3 個種子 |
| LLM | 評測使用確定性的 FakeLLM（免費、可重現）；真實 Opus 5.5 只在 Phase 2–3 做過端對端驗證（見 §6 限制） |
| 評分 | 確定性評分器（`evals/scorer.py`）：主張是否與標準答案的網站與範本一致、首個關鍵證據抓取數、浪費率、LLM 花費、步驟數、幻覺、伺服器判定的安全違規 |

重現方式見 §7。

## 2. RQ1：可觀察的研究迴圈

### 2.1 結果

| 指標 | 結果（測試集 18 個 episode，Day 1，無記憶） |
|---|---|
| 正確率 | 18 / 18（F1 = 1.00） |
| 平均抓取次數 | 36.6 次（預算 300；主要競品約 2 萬頁） |
| 首個關鍵證據 | 中位數第 17 次抓取（其中約 12–15 次是 robots 與 sitemap 探勘） |
| 浪費率 | 2.5%（403、404、429、逾時、陷阱頁 ÷ 對網站的請求） |
| 安全違規 | 0（robots、crawl-delay、超速、登入頁，由 SimWeb 伺服器判定） |
| 緊縮預算 | 抓取上限 20：17 / 18 正確；上限 30：18 / 18 正確 |
| 真實 Opus（Phase 2–3） | s1、s3 正確，信心 0.98 / 0.94，每個 episode 約 US$0.31–0.32，報告引用全部有效 |

### 2.2 可觀察到什麼

- **即時主控台**與 `--step` 逐步模式：8 個步驟、每個候選行動的分數明細與理由、LLM 結構化輸出與花費、HTTP 請求、預算條。
- **`timeline.html`**：結論與證據表、假設信心隨每筆證據變化的曲線、範本統計（含記憶先驗與避開標記）、資訊需求、自治邊界（核准、限制、安全事件）、可展開的步驟時間軸。
- **報告**：主張由程式從證據推導、每個引用都經過驗證；標題由程式產生；系統補上的限制（人工拒絕、預算用盡、安全事件）不依賴 LLM 是否提到。

### 2.3 研究發現

1. **可觀察性本身就是除錯工具**：真實 LLM 給出多組關鍵字反而讓主題頁被誤判為非主題頁——這是從 trace 中「2,578 字的長照險指南被標為非主題頁」一行看出來的（Phase 2）。
2. **確定性替身無法取代真實 LLM**：時序中位數冤枉漸進式上線、紅隊以數量壓倒證據、排序選樣高估變動率，都只在真實 Opus 執行時暴露（Phase 3）。
3. **背景變動會被誤認為策略變動**：「同範本累積 3 頁變動」在大量標籤頁的網站上誤判；改用競爭假設 + 鑑別性證據（SERP 排名網址、更新爆發度、隨機抽樣 + 二項檢定）後改正（Phase 2 → 3）。
4. **觀察到的最早日期只是上限**：Agent 抓得越少，觀察到的最早變動日越晚，時序探針就越容易把真正的原因判為「晚於排名變化」。Phase 6 評測中 s6 有 2 個種子因此得出「無結論」；改為只有看過範本中至少一半的期間內變動頁時才算強烈反證後全部正確。這是 Phase 3 發現 1 的延續——同一個偏誤在樣本更少時再次出現。

## 3. RQ2：經驗回流

### 3.1 評測協定（`seo-intel eval protocol`）

1. **Day 1**：空記憶，測試集 s5、s6 × 3 個種子。
2. **訓練**：訓練集 s1–s4 × 3 個種子，共用一份記憶；腳本化的「人類」只在主張與標準答案不符時，依標準答案寫出糾偏理由。
3. **Day N**：訓練後的記憶凍結，在同一測試集重跑；每個 episode 用快照的副本，跑完即丟（測試集永不寫回記憶）。
4. **消融**：Day N 分別關閉 M1、M2。
5. **緊縮預算**：抓取上限 20、30，Day 1 與 Day N 各跑一次；無人值守時核准請求一律拒絕。

### 3.2 主要結果

**各種子組**（每組 6 組配對；同一情境、同一種子，Day 1 → Day N）：

| 種子組 | 在開發中是否看過 | Day 1 平均抓取 | Day N 平均抓取 | 變化 | 配對差異 95% CI | LLM 花費 | 步驟 |
|---|---|---|---|---|---|---|---|
| 原種子 | 看過：兩個修正都是依它診斷 | 36.7 | 29.7 | −19% | −17.0 ～ +0.8 | −4% | −19% |
| +5000 | 第一個修正後才首次使用 | 36.7 | 27.0 | −26% | −12.0 ～ −7.3 | −15% | −39% |
| **+8000** | **兩個修正完成後才首次使用（最乾淨）** | 36.3 | 25.7 | **−29%** | **−18.0 ～ −6.0** | −12% | −41% |
| 合併 18 組 | — | 36.6 | 27.4 | **−25%** | **−13.6 ～ −5.3** | −10% | −33% |

- 18 組中 16 組抓取減少、1 組增加（s5 種子 2505：43 → 48）、1 組持平；正確率 Day 1 與 Day N 都是 18 / 18。
- 首個關鍵證據抓取數**沒有變化**（中位數 17 → 17）。
- 浪費率沒有變化（2.5% → 2.5%）；幻覺（未驗證主張、無效引用）兩者皆 0；安全違規 0。
- 緊縮預算：成功率相同（上限 20：17 / 18 vs 17 / 18；上限 30：18 / 18 vs 18 / 18），但**需要人工核准的次數** 18 → 11（−39%）、9 → 5（−44%）。

**消融**（合併 18 組，相對於 Day N 的抓取差異）：

| 條件 | 平均抓取 | 相對 Day N | 解讀 |
|---|---|---|---|
| Day N | 27.4 | — | — |
| 關閉 M1（只剩 M2 先驗） | 36.8 | +9.4（CI +6.5 ～ +12.6） | 回到 Day 1 水準：效益幾乎全部來自 M1 |
| 關閉 M2（只剩 M1 經驗） | 25.7 | −1.7（CI −4.1 ～ +0.4） | M2 沒有可測得的貢獻，甚至略為負面 |

**學到的記憶**：訓練後生效的經驗只有兩條，都來自成功的 episode，且都是程式可套用的偏置：

| 經驗 | 內容 | 套用位置 |
|---|---|---|
| L-1 | 答案範本在探勘階段就有訊號（SERP 排名網址、期間內更新爆發）→ 先抽樣有訊號的範本；訊號範本已有足夠證據候選時直接進入假設檢驗 | `sampling`、`early_hypotheses` |
| L-2 | 免費證據已讓主要假設 ≥ 0.9、其他 ≤ 0.2 時，付費探針不會改變結論 | `seek` |

三組評測的訓練都是 12 / 12 正確，因此沒有發生人工糾偏；訓練中也沒有遇到封鎖或 JS 空殼頁，所以沒有產生失敗經驗（WAF 經驗的學習只在 Phase 4 的 s5 連跑實驗中出現：封鎖 2 → 2 → 0）。

### 3.3 研究發現

1. **學習省下的是「找到之後」的冗餘，而不是「找到之前」的探索**：首個關鍵證據抓取數完全沒變，因為它主要由探勘成本（robots、sitemap 約 12–15 次）決定；學習減少的是之後對其他範本的普查與定向抓取。要讓 Agent 更早找到答案，需要不同的學習目標（例如學會先看哪個網站的哪個 sitemap）。
2. **經驗必須改變「做多少」，而不只是「先做什麼」**：第一版 `sampling_focus` 只改抽樣順序，s1 第 3 次反而比第 2 次多抓（Phase 4）。
3. **經驗的本意要落實到停止條件**：Phase 4 的版本在跳過普查後進入「定向抓取」，但定向抓取的停止條件是「連續 15 次沒有證據候選」，經常更新的產品頁每頁都像證據，結果單一範本抓到上限。評測中 s5 有 2 個種子因此**學習後反而多抓**（43 → 58、43 → 54）。改為「訊號已足夠就直接進入假設檢驗」後才穩定改善。
4. **效率修正可能帶來正確性退步**：上一點的修正讓 Agent 更早進入假設，抓的頁面變少，觸發了 RQ1 §2.3 第 4 點的時序偏誤，s6 一個種子從正確變成無結論。效率與正確性必須一起評測，只看抓取次數會漏掉這種退步。
5. **M2 的跨站遷移幾乎沒有幫助**：範本價值先驗讓抽樣變稀疏（低價值範本只抽 1 頁），但先驗常來自其他網站的同類路徑——訓練情境中的 `category/{slug}` 都是干擾項，測試情境 s5 的答案卻正是 `category/{slug}`（負遷移）。M1 已經用「探勘訊號」做了更好的聚焦，M2 的先驗反而增加雜訊。
6. **學習減少了人被打斷的次數**：在緊縮預算下，學習後的 Agent 需要人工核准延長預算的次數約少 40%。這是自治邊界與學習機制交互作用下的實際效益，原本不在評測指標中。

### 3.4 方法論：測試集調參的洩漏與處理

兩個修正（第 3 點、時序覆蓋率）都是看了測試情境（s5、s6）在原種子上的結果才發現的，這構成**測試集洩漏**：依測試結果調整後，再用同一批測試結果宣稱進步並不可信。處理方式：

- 種子是 SimWeb 的世界參數，換種子就是從沒見過的世界（網址、頁面、雜訊都不同，因果結構相同）。
- +5000 組在第一個修正後才首次使用；**+8000 組在兩個修正都完成後才首次使用**，是本研究最乾淨的證據（−29%，CI −18.0 ～ −6.0，6 / 6 正確）。
- 原種子組的結果仍列出，但標明「開發中看過」。
- 用正式 CLI 重跑 +8000 組，結果與先前完全一致（確定性可重現）。

這個流程本身也是一個發現：**沒有 holdout 的種子，很容易在不知不覺中對測試集過擬合**——第一輪評測時 s5 有兩個種子學習後變差，若只修到原種子變好就停下，會高估效果。

## 4. RQ3：自治邊界與失效處置

| 類別 | 結果（`tests/test_autonomy.py`、`tests/test_failures.py`、Phase 4–5 實驗） |
|---|---|
| 禁止動作 | 偽造 UA / 輪替 IP / 繞過驗證的參數、登入區域、robots 禁止、範圍內來源不明的網址：全數拒絕；LLM 無法發明工具（工具名稱是封閉型別） |
| 需核准動作 | 範圍外網域、調高速率、大量抓取、預算用盡、封鎖率過高：全數硬暫停；政策沒有列出的規則一律需核准（fail-closed） |
| 核准流程 | 暫停 → 核准 → 續跑完成；拒絕 → 以現有證據下結論並寫入報告限制、同一範圍不再詢問；過期核准無效；決定寫入 trace（`HUMAN_DECISION`） |
| 被攻陷的 LLM | 每個角色都照注入頁指示輸出：沒有任何請求送到攻擊者網域、違規 0、攻擊者假設被拒收、10 個灌水反駁不計分、結論正確、報告中的指控與指令文字全部刪除 |
| 注入頁 | 被抓到時：標記安全事件、不採用其連結、指令要求的網址沒有被抓、LLM 從頭到尾看不到指令文字 |
| 混沌 | LLM 40% 暫時性錯誤 + 10% schema 錯誤：12 / 12 正確；網路 25% 逾時 / 連線失敗：4 / 4 正確；解析器 15% 崩潰：正確；程序硬中斷：從最近檢查點續跑，結論相同、trace 無重複或缺號 |
| 錯誤經驗 | 植入「避開答案路徑」的錯誤經驗：2 次與證據衝突後自動淘汰；錯誤的人工糾偏：被遵守，與證據衝突時只標記「建議人工檢視」，代價是成本上升而非結論改變 |

研究發現（詳見 [03 Phase 4–5](03-implementation-plan.md)）：

1. **結構性防禦比偵測可靠**：LLM 只看程式整理過的事實、行動只能由程式產生、主張由程式推導，所以 LLM 被完全攻陷也無法讓 Agent 越界。樣式掃描只是補強——一般情境下 Agent 根本不會抓到注入頁（6 個情境 0 次）。
2. **但 LLM「看得到的文字」仍是缺口**：研究目標的關鍵字曾直接收下指令文字；引用驗證曾只刪除無效引用、留下沒有根據的指控。兩者都在被攻陷的 LLM 實驗中才暴露。
3. **核准疲勞是真實成本**：預估不含重試餘裕時，一次核准會變成兩次；拒絕後若不記住範圍，同一個問題會被反覆詢問。
4. **一個暫時性錯誤會抹掉一整類證據**：排名掃描一次發出十幾個 API 請求，任一個失敗就整批作廢；10% 網路錯誤時一半的 episode 得不出結論，加上連線重試與行動層重試後全部正確。
5. **錯誤經驗的代價主要是成本**：污染經驗與錯誤的人工糾偏都沒有改變結論，但會增加抓取；兩者疊加時曾讓定向抓取把 104 次抓取花在標籤頁，暴露出與記憶無關的成本控制漏洞（每範本上限）。

## 6. 限制

1. **評測只用 FakeLLM**：FakeLLM 是確定性的規則式替身，它的假設、探針規劃與報告比真實 LLM 簡單；RQ2 的效率改善主要來自程式套用的偏置，對真實 LLM 應同樣有效，但 LLM 花費的改善與正確率在真實 LLM 下未經驗證。完整協定的真實 LLM 評測約 54 個 episode、US$19（`--quick` 約 18 個、US$6）；本研究決定以 FakeLLM 評測收尾，真實 LLM 評測列為未來工作（§8），指令已就緒（§7）。
2. **模擬環境**：SimWeb 的網站、排名與歷史都是合成的；真實網站的雜訊、反爬與 sitemap 品質更不可控。
3. **樣本小**：每組 6 組配對、合併 18 組；信賴區間以 bootstrap 估計，區間偏寬。情境只有 6 個、2 種目標類型。
4. **Day 1 已經很好**：正確率沒有改善空間，RQ2 只能在效率上回答。需要更難的情境（Day 1 會失敗、經驗能救回的）才能測學習對正確性的影響。
5. **人工糾偏未在協定中被觸發**：糾偏流程與遵循已在 Phase 4 驗證，但沒有在 Day 1 / Day N 協定中產生可量化的效益。

## 8. 未來工作

| 方向 | 理由 |
|---|---|
| 真實 LLM 的 Day 1 / Day N 評測 | 驗證效率改善在真實 LLM 下成立，並量測真實的 LLM 花費變化 |

| 依網站類型加權的 M2 | 目前的跨站先驗會負遷移；以網站類型或範本角色相似度加權，或在 M1 已聚焦時停用 |
| 更多 holdout 種子與情境 | 縮小信賴區間；正式區分開發用與最終評測用的世界 |
| 真實網站（需授權） | 研究範疇外；需處理真實反爬、法律與資料品質 |
